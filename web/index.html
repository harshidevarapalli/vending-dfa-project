01 · States

It remembers one number.

A DFA has no memory except which state it is in. For this machine that's the balance. “₹15 inserted” isn't stored anywhere; it is state q15.

8states in Q

02 · Transitions

One arrow per symbol. Always.

Every coin and button is a symbol in Σ. From any state, each symbol has exactly one arrow: that's the deterministic in DFA. Press keys and watch the highlighted row and arrows.

03 · Accept or trap

Two ways to end: q_done or q_dead.

A transaction is one input string w. It's accepted if it ends in the accepting state (double ring). Overpaying, buying what you can't afford, or pressing anything after a purchase drops it into the trap, which has no exit.

04 · Output

The DFA decides. The Mealy machine acts.

A plain DFA only says yes or no. The Mealy layer λ(q, a) attaches a physical output to every arrow: dispense, give change, refund, or beep.

05 · Minimisation

16 states in, 8 out.

The first design had a separate “done” state for every product-and-change combination. Hopcroft's algorithm proved they're indistinguishable: no future input can tell them apart. So they merge into one q_done.

06 · Why it's regular

The cap is what makes it finite.

Without a limit, every extra coin would need a new state (q30, q35, q40…), forever. No finite automaton can do that. The ₹25 cap cuts the list off, so Q is finite and the language is regular.
